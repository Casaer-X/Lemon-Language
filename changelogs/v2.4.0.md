# v2.4.0 Changelog

## [2.4.0] - 2026-05-24

### Phase 1: Core Feature Completion

Major feature additions to bring the Lemon compiler's C code generation to parity with the Rust version.

#### 1.1 Generic Instantiation

- **New data structures**: `genericInstances` (Map<String, Array<Array<TypeRef>>>) and `genericClasses` (Map<String, ClassDecl>)
- **Collection phase**: `collectGenericInstances()` scans AST for all `new ClassName<TypeArgs>(...)` expressions, field types, method params/returns, and ForEach element types
- **Name mangling**: `mangled_generic_name()` generates C identifiers like `Pair_int_String`, `Map_String_int`
- **Type substitution**: `substitute_type()` and `build_type_param_mapping()` replace type parameters with concrete types
- **Code generation**: `generate_generic_struct_def()`, `emit_generic_struct_defs()`, `emit_generic_forward_decls()`, `emit_generic_implementations()` generate complete C code for each generic instance
- **Integration**: Modified `ct()`, `genNewExpr()`, `emitForwardDeclarations()`, `emitImplementations()` to handle generic instances

#### 1.2 Method Overloading Resolution

- **Multi-signature storage**: `methodSignatures` changed from `Map<String, Array<Param>>` to `Map<String, Array<Array<Param>>>` to store all overloads
- **Name mangling**: `type_ref_mangle()` encodes types as short strings (int→"i", String→"string", Array<int>→"ai"), `mangle_method_name()` generates `ClassName_method_i_string` for overloaded methods
- **Overload resolution**: `resolve_method_overload()` selects the correct overload by argument count at call sites
- **Built-in type exemption**: String, StringBuilder, LemonArray, LemonMap, System, Character, File use simple names without mangling (except `String.substring` which has `substring_from`/`substring_from_to`)
- **No mangling for single overloads**: When only one method with a given name exists, the simple `ClassName_methodName` format is used (backward compatible)
- **Integration**: Modified `emitMethod()`, `emitConstructor()`, `emitCtorMethod()`, `genObjMethodCall()`, `genNewExpr()`, `genCallExpr()`, vtable/itable generation

#### 1.3 StringBuilder Runtime Completion

Added 11 missing StringBuilder methods to the C runtime library:
- `StringBuilder_appendLong(int64_t v)` - snprintf with %lld
- `StringBuilder_appendFloat(float v)` - snprintf with %g
- `StringBuilder_appendDouble(double v)` - snprintf with %g
- `StringBuilder_appendBool(int32_t v)` - "true"/"false"
- `StringBuilder_setCharAt(sb, idx, c)` - bounds-checked character assignment
- `StringBuilder_charAt(sb, idx)` - bounds-checked character access
- `StringBuilder_deleteCharAt(sb, idx)` - memmove-based character deletion
- `StringBuilder_insert(sb, idx, s)` - memmove + memcpy string insertion
- `StringBuilder_clear(sb)` - reset length to 0
- `StringBuilder_free(sb)` - free buffer and struct
- `StringBuilder_capacity(sb)` - return current capacity

Updated `SemanticAnalyzer.isBuiltinTypeMethod()` to recognize all new methods.

#### Bug Fixes

- **LemonMap_put use-after-free**: Removed `free(oldEntries[ri].key)` during rehashing — the key pointer was copied to the new entry before being freed, causing dangling pointers and memory corruption
- **void* chained method calls**: Fixed `isStringReturningMethod()`/`isStringReturningFunction()` to use `String.equals()` static method instead of `.equals()` on void* return values
- **void* field access**: Fixed all `params.get(i).paramType` patterns to use explicit casts: `Param pp = (Param)params.get(i); pp.paramType`
- **Type inference for const char***: `inferClassFromExpr()` now correctly returns "String" when element type is `const char*` (not just pointer types ending with `*`)
- **Element type inference**: Added `stringReturningMethods` and `stringReturningFunctions` to `inferArrayElementTypeFromFieldName()`
- **MatchBody access**: Fixed `collect_generic_instances_from_stmt()` to handle MatchBody's `block`/`expr` structure instead of non-existent `statements` field
