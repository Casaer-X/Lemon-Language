# v1.7.0 Changelog

## [1.7.0] - 2026-05-23

### Type Inference Refactoring (C.1.1)

Replaced hardcoded field-name-to-type mapping with AST-collected type information, making the type inference system more robust and extensible.

#### Changes

- **New `classFieldElementTypeMap`**: Collects `Array<T>` element types from `TypeRef.elementType` during `collectClassFields()`, eliminating the need to guess element types from field names alone
- **New `localVarElementTypes`**: Tracks element types for local variables and method parameters declared as `Array<T>`, preventing type inference failures for variables like `paramCtypes`
- **Improved `inferArrayElementTypeFromFieldName()`**: Now queries in priority order:
  1. `localVarElementTypes` (method params, local vars)
  2. `classFieldElementTypeMap` for current class
  3. `classFieldElementTypeMap` for all classes (cross-class access)
  4. Hardcoded conventions (backward compatibility fallback)
- **Element type collection in all code generation paths**: `emitMethod`, `emitCtor`, `emitCtorMethod`, `emitFunction`, and `emitStmt(VarDecl)` now record `Array<T>` element types

#### Impact

- New Lemon programs with `Array<T>` fields no longer need manual registration in hardcoded lists
- Type inference works correctly for any `Array<T>` where `T` is known at compile time
- Backward compatible: hardcoded fallback ensures existing code continues to work

### Bootstrap Verification
