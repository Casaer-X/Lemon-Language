# v2.6.0 - 语义分析增强

## 概述

Phase 7 完成：语义分析器增强，新增枚举变体检查、访问权限检查和 Match 完备性检查。

## 新功能

### 7.1 枚举变体语义检查

- 新增 `isEnumType(typeName)` 方法：判断类型名是否为枚举类型
- 新增 `enumHasVariant(enumName, variantName)` 方法：检查枚举是否有指定变体
- 在 `checkExpr` 的 FieldAccess 分支中增加枚举变体访问检查：`EnumName.VariantName` 形式访问时，验证枚举类型和变体名
- 在 `checkExpr` 的 Call 分支中增加枚举变体构造调用检查：`EnumName.VariantName(args)` 形式调用时，验证变体存在性

### 7.2 访问权限检查

- 新增 `isSubclassOf(childClass, parentClass)` 方法：检查类继承关系
- 新增 `getMethodModifiers(className, methodName)` 方法：获取方法的修饰符（支持继承链查找）
- 新增 `getFieldModifiers(className, fieldName)` 方法：获取字段的修饰符
- 新增 `isAccessAllowed(targetClass, memberModifiers, accessingClass)` 方法：检查访问权限
- 在 FieldAccess 分支中增加访问权限检查：访问 private 成员时验证调用者是否在同一类内
- 在 MethodCall 分支中增加访问权限检查：调用 private 方法时验证调用者是否在同一类内
- 在静态成员访问（`ClassName.member`）中也进行访问权限检查

### 7.3 Match 完备性检查

- 新增 `inferEnumTypeFromExpr(expr)` 方法：从表达式推断枚举类型名（支持 Variable 和 FieldAccess）
- 新增 `collectCoveredVariants(pattern, covered)` 方法：从 match 模式中收集已覆盖的变体名（支持 Or 模式）
- 在 `checkExpr` 的 Match 分支中增加完备性检查：
  - 如果没有通配符 `_` 且 match 目标是枚举类型，检查是否所有变体都被覆盖
  - 缺少变体时报告 `NonExhaustiveMatch` 错误，列出缺失的变体名

## Rust 版同步更新
